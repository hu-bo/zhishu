# 授权实现与验收

知书使用 PostgreSQL 保存当前授权关系，node-Casbin 执行角色/操作策略。`authorization/policy.ts` 是内置策略唯一来源；单资源检查使用 Casbin，列表使用相同映射生成 SQL，在分页和计数前过滤。只缓存不可变策略配置，不缓存用户授权结果。

## 资源、主体与来源

`resource_acl` 统一保存空间、目录和文档角色绑定，三个资源外键必须且只能设置一个，并用租户复合外键约束。`role_permissions` 保存空间内角色策略覆盖。默认角色为 admin/editor/viewer；旧 read/write/comment/share/export/ai/manage 授权保守保留，单独 write 不隐含 AI。

团队空间使用独立 ownerIdentityId；个人空间仍以 personalOwnerId 为准。文档 createdBy 仅供审计，不能绕过当前成员关系。团队继承文档接受空间和可继承祖先目录授权；restricted 目录截断上级，文档 restricted/personal 不继承。直接文档授权按来源并集，移出空间不删除独立授权。

身份提供方输出可信 Principal，HTTP guard 在拒绝 active=false 前同步身份投影。可信后台同步也可调用 rememberIdentities，不能将客户端传入的 active 当成权威。状态变更与租户授权锁、版本及事件同步，已建立协同会话会被关闭，SQL/Casbin 也拒绝已停用主体。外部停用通知到达应用前的时延由身份适配器负责，应用没有另造账号禁用角色或接口。

空间发现要求空间 read。单独文档授权不会带出空间名称、描述、成员或根目录；列表/搜索/定位显示“与我共享”，逐祖先检查目录 read。不可读父级不会阻止合法共享子文档访问。前端独立共享视图保留文档能力，隐藏空间设置、成员和目录入口。

## 分享链接

新 UI 默认创建 access；旧 API 未传 kind 时保持 invite 兼容：

| 类型            | 加入后的授权                                             | 撤销/过期                                              |
| --------------- | -------------------------------------------------------- | ------------------------------------------------------ |
| invite 长期邀请 | 每条链接的来源独立保存，接受后成为长期授权               | 停止公开访问和新加入；已接受授权需在成员权限中独立移除 |
| access 限时访问 | 绑定 sourceShareId，实时检查链接状态与创建者当前委托资格 | 仅该来源失效，保留其他有效链接、邀请或手动授权         |

创建阅读链接需要 read + share；编辑链接额外需要 write + comment。委托资格只由空间/目录/手动/长期邀请等持续授权计算，不接受其他 access 来源，避免循环转授权。普通链接只授 read/comment/write，不授管理、分享、导出或 AI。加入保存独立来源，同来源重试不重复计数，已有阅读权可以升级。

公共详情、正文、附件和加入均复核当前委托资格；匿名正文始终只读。公共读页定期复核状态并在已知到期时隐藏正文；附件预签名 TTL 取配置值和剩余有效期的较小值，已签发 URL 无法在撤销时追溯收回。旧无 sourceShareId 的 ACL 不根据授权人猜测来源，也不自动批量撤销。

## 治理与搬运

空间设置的角色权限页支持所有者修改策略、切换本机正文缓存、转移团队空间所有权和显式恢复受限文档管理。所有权转移验证当前版本、当前所有者和有效真实成员；旧所有者成为 admin，createdBy 保持审计语义。治理恢复要求填写原因，写入显式 manage 兼容授权和同事务审计。

ACL、成员、角色策略、访问模式和目录/文档移动删除校验结果仍有有效且具有 read + manage 的管理主体。外部账号停用不能被本地授权回滚；如唯一管理员被外部停用，需可信身份恢复或仍有效的空间所有者显式治理恢复。

模板复制要求源文档 export 和目标空间组织权。跨空间文档/目录移动先请求影响预览，验证全部文档的 export，并绑定调用主体、目标目录、源/目标授权版本、元信息版本及子树关系；提交时在锁内重算，不匹配返回冲突。移动撤销旧公开链接，保留已提示的独立授权，并验证管理连续性。目录删除影响预览不向无权主体泄露隐藏文档计数。

目录 ACL **按用户要求延期**。目录树和浏览页仅向 canManage 用户展示禁用的“目录权限 · 规划中”。未来由 CatalogActionDialogs / CatalogService 复用现有 resource_acl、catalogActionSql 与事务协议，开放前另行完成目录逐成员授权、断继承、冲突及子树撤权验收。

## 事务、会话与离线

授权关系变更持 knowledge-tree 租户排他事务锁；正文持久化、标题、版本、附件与评论写入先持同键共享锁，再获取文档行锁。业务事务内重新判权，拒绝落盘不发 durable ack。分享授权、计数、通知及审计一并提交，失败回滚。

授权触发器在原事务内增加空间 authorizationRevision 并写 authorization_events（actor、资源、操作、前后状态）；分配事件 ID 前持全局短事务锁，保证消费者不会越过尚未提交的低 ID。每个 API/协同 owner 独立读取有序 outbox，成功后前移本地游标，失败不跳过。实例启动没有旧房间，游标从当前最大值开始；事件关闭本地相关会话，新会话必须重新授权。访问链接到期扫描同样关闭连接，不依赖后续业务写入。每次写入授权检查始终是最终防线。

授权状态接口仅返回可读空间的 ID、版本、缓存策略及自身来源到期指纹/下一期限。前端每 5 秒及聚焦时复核，变化后清理接口缓存和已确认协同快照，保留未确认草稿并重新加载查询。缓存写入串行，请求记录授权代次，旧在途响应不会跨代回写；身份命名空间防止串号。已知链接到期后离线缓存拒绝读取，须在线校验后恢复。

关闭 offlineCacheAllowed 后不新写正文/导出缓存和协同快照，也不自动回放旧待确认内容。未确认草稿隔离保留供恢复/导出。完全离线且尚未得知撤权的已下载内容不能远程收回。授权拒绝使用带请求上下文的结构化日志；空间审计与文档来源均有受保护查询入口。

## 迁移与验收

永久删除在级联删除前将代次 ID 写入同事务事件，实例即使查不到原文档也能关闭旧房间。正文代次状态切换同样生成失效事件，消费者关闭当前与历史代次，避免仅查 active 代次漏掉旧连接；双消费者回归覆盖这两种边界。

按序应用 0038（统一授权表）、0039（旧受限文档显式管理兼容）、0040（所有者/来源/策略/版本/审计 outbox）和 0041（身份状态）。0039 不给正常团队继承文档回填创建者特权；0040 不猜测旧分享来源。部署时须退出全部旧实例，避免混用写入锁协议。本轮只使用隔离数据库，没有操作开发/生产数据。

```shell
# 默认隔离 PGlite：真实 migration、约束、SQL 与 Fastify HTTP
pnpm --filter @react-fastify-template/app-server test:authorization

# 空的本机独立 PostgreSQL，库名必须以 zhishu_permission_test_ 开头
# 设置 AUTHORIZATION_TEST_DATABASE_URL 后执行：
pnpm --filter @react-fastify-template/app-server test:authorization:postgres

# 整仓交付检查
pnpm check
```

真实 PostgreSQL 使用独立回环临时实例，验证多连接 revoke/join、成员移除/写入排队、两个独立 outbox 消费者、真实 Hocuspocus WebSocket 合法编辑落盘/确认，以及撤权/只读伪造拒绝。默认 PGlite 覆盖 SQL/Casbin 等价、租户边界、迁移兼容、所有者转移、治理恢复、来源撤权/自然到期及故障回滚，不将其称为多连接证明。浏览器夹具用于界面和 IndexedDB 检查，正文协同真实性由真实 WebSocket 用例验证。最终结果记录在审查文档顶部。
