## 1. 产品职责与现有基础

沿用 React、Vite、TypeScript、TanStack Router/Query、React Hook Form、Zod、Orval 及现有基础 UI。`orval.config.ts` 从 `apps/app-server/openapi.json` 生成客户端，根级 `pnpm check` 会运行前端类型检查、构建与生成漂移检查。

已实现的 WEB-01 工作台将 view、搜索词、排序、方向和 offset 保存在 URL；支持最近/我的/全部/收藏/归档/回收站视图、创建、标题查询、服务端排序分页、收藏切换、归档、移入回收站、恢复与永久删除确认。回收站列表显示移入时间，恢复和永久删除按钮按 owner 能力禁用，并显示处理中状态；服务端仍复核授权。自动保留期限和过期清理策略尚未定义，当前不自动永久删除回收站内容。列表接口仅返回 `canManage` 能力布尔值，不向浏览器暴露创建者身份。开发模式可通过 mock 登录取得短期 bearer token，token 仅保存在当前页面内存，刷新后需重新登录。生产身份仍由宿主接入。

支持两个产品配置：独立文档入口只需要文档、身份、授权和协同服务；企业平台配置增加空间、知识库、AI、评论与管理。页面是否出现由服务端返回的可用能力和当前用户权限共同决定，隐藏菜单不代表后端已经授权。

文档页的编辑/阅读模式是按文档保存的本地界面偏好，不改变内容模式或服务端权限。Provider 通过即时 `editable` 切换，阅读模式隐藏编辑工具并保留查找、大纲和业务分享/导出；协同状态错误、拒绝或服务端只读仍会覆盖本地编辑偏好。Chromium 已在实际协同页验证切换时工具显隐及会话不重建；服务端只读用户和刷新恢复仍待回归。标题 Emoji、彩色标签、作者与相关文档字段尚未接入当前 API。

### 工作台视觉规格

syncscribe 的桌面基线为 288px 展开导航、56px 收起导航和约 288px 右侧大纲；中间画布根据剩余宽度伸缩，正文目标最大宽度 896px。知书沿用该尺寸作为桌面起点，中小屏将左右栏改为可关闭抽屉。页面使用 Slate 50/100 画布与白色面板，品牌强调采用 Indigo 600；暗色使用 Slate 900/950。文档编辑页正文使用 16px 字号、1.75 行高，工作台界面文字以 14px 为默认值。

颜色、边界、圆角、阴影与焦点态已由全局语义变量提供，并映射到 `--zhishu-ui-*`；编辑器包保留独立默认值，可由单个实例覆盖。app-shell 已提供亮色、暗色和跟随系统选项并保存偏好；桌面导航支持 288px/56px 展开收起，移动导航使用 Dialog 抽屉，关闭后焦点返回触发按钮。编辑器现由应用层组合独立的大纲和详情栏：桌面详情宽 288px、可收起；窄屏由编辑器页头按钮打开 Dialog 抽屉。面板展示正文大纲、模式、创建/更新时间和真实的管理能力。大纲高亮按当前编辑器 heading Block 与最近可滚动祖先更新；消费样例滚动至文档后段时已观察到当前标题切换。当前 API 没有作者、标签和相关文档字段；重复标题、远端改动、路由中的滚动行为及详情抽屉焦点恢复仍需专项验收。

## 5. 关键用户流程

### 新建与首次打开

用户选择空白/模板 → 服务端创建文档并初始化一次内容 → 跳转稳定 documentId → 请求会话与权限 → 等待协同状态加载 → 展示编辑器。创建按钮有请求中状态；工作台对相同创建参数复用 `Idempotency-Key`，失败保留标题/模板选择，API 在 24 小时内重放原创建响应；其他写路由幂等待接入。

首次打开区分不存在、无权限、回收站、Schema 不兼容和服务不可用。权限错误可以使用服务端统一的资源不可见语义；不能用失败的内容请求初始化空文档。

### 编辑、保存与离开

正文由 core/collaboration 管理，页面分别展示连接和持久化进度。标题与其他元数据走带 metadataRevision 的 API，不与正文全文保存混用。应用内路由切换或退出登录遇到未确认修改时，提示用户继续编辑、放弃修改，或下载符合 `zhishu.document` v1 的 JSON 草稿后离开；浏览器刷新/关闭使用原生离开提示。Playwright 本地 Chromium 已验路由离开提示、继续编辑、导出后离开，导出文件格式及正文正确；刷新触发原生提示，取消后草稿仍在当前页面。断网产生 pending 更新时，路由切换和登出均显示三种处理选项；继续编辑后恢复联网，更新收到 durable ack 并保存至序号 3。草稿不包含图片文件。关闭浏览器前的异步请求不作为可靠保存手段。

### 版本与恢复

用户选择历史版本 → 只读查看/对比 → 明确恢复会形成新当前代次 → 服务端恢复并返回新 generation → 页面重建会话。协同恢复已在本地浏览器确认，命名/自动版本、差异预览和重新登录重开验收通过。历史附件引用保留、当前引用清空后的保留，以及文档永久删除后的对象清理均已在临时 MinIO/PostgreSQL 验收。版本差异通过只读历史内容 API 读取，不另建可写 Y.Doc。其他协作者收到变化提示；当前未保存内容可保留为副本，不能静默丢弃。评论锚点无法映射时显示原版本及失效状态。

### 上传与导入

选择/粘贴文件 → 上传服务返回进度 → 服务端确认可引用资产 → core 按有效锚点插入。失败在对应位置提供重试/取消；取消或目标被删除时不插入正文。导入先预览格式兼容报告，再创建文档或执行明确插入，不直接覆盖当前协同内容。

文档页的传输操作允许导出服务端已保存的 JSON 包、独立 HTML、Markdown（CommonMark/GFM）或纯文本，并导入为新文档。转换会在继续前显示格式损失；图片和 PDF 资产不能跨文档导入。打印/PDF 先通过现有导出权限读取已保存正文，在独立窗口只呈现正文与标题，私有附件使用文字占位，代码换行、表格重复表头并控制分页。该入口不导出未确认的本地修改，也不提供异步大任务队列或任务状态。

`features/knowledge` 管理真实工作区切换、递归目录、子页创建、原位重命名、删除、拖拽与键盘可替代移动。目录冲突保留当前输入/移动目标，允许重新加载目录后重试。面包屑根据当前文档工作区及可见父链生成；工作区偏好按租户/身份隔离。全局 Ctrl/Cmd+K 搜索支持标题与正文片段、可见祖先路径、关键词标记、全工作区筛选、方向键与 Enter；新输入和关闭弹窗取消查询，Escape 回到之前焦点。编辑器选中文本时快捷键优先打开链接操作，输入法组合期间不接管按键。

文档信息面板可编辑单个 Emoji 和最多 12 个彩色标签，真实创建者/时间及标签也显示在详情栏。PATCH 携带 metadataRevision，冲突保留输入并刷新基础修订。阅读模式保留查找、大纲和授权分享/导出，切换不重建编辑器；服务端写权限独立生效。任务完成动效由个人开关控制，默认关闭，并遵循减少动画偏好。

### 离线缓存与草稿恢复

`features/offline` 用 IndexedDB 保存最近授权读取的目录、元信息、正文与草稿，按 API、租户、身份、工作区、文档、generation 和内容格式隔离。所有文档使用同一协同检查点，保存正文投影、基础结构修订和未收到 durable ack 的原生 Yjs 更新。凭据及附件授权 URL 不写入缓存。

生产构建生成仅缓存公共页面资源的 Service Worker，需 HTTPS 或 localhost；开发构建可设置 `VITE_ENABLE_OFFLINE=true` 验证。资源完整安装后启用新缓存，保留最近两份页面资源；API 不进入 Service Worker 缓存。未缓存文档显示不可用范围，不能把读取失败当空正文。

断网刷新允许本机恢复上次已校验账户的缓存资料，显示离线/权限待校验提示，不以缓存身份签发网络写入。联网后重新登录并检查权限。缓存离线刷新为只读；新会话校验权限、generation、格式和结构修订一致后重放未确认原生更新，等待 durable ack 后清除待确认记录；不一致则保留副本，禁止将旧整文 JSON 灌入当前会话。

401 清理授权响应和缓存账户，403/404 清理受影响文档及包含它的目录/列表；未确认草稿保留供导出。退出前处理未确认修改并清除该身份缓存。IndexedDB 不可用、空间不足或页面缓存安装失败均显示提示与导出入口；本机缓存成功和服务器保存成功分别表达。

### 知识问答与 AI 创作

以下为 2026-10-21 更新的页面与业务设计。创作路由、Chat API、两种写入模式和服务端接受链路已实现，验收范围见本文开头；知识域检索、继承权限等后续设计仍按各节边界推进。用户所指 `apps/web` 对应仓库实际目录 `apps/app-web`。

问答选择的知识域由服务端验证，UI 展示来源文档、版本和片段。没有可用证据时明确说明；引用打开再次请求权限。流中断保留已展示文本并标记不完整，不把部分答案当完成结果。

待审的 Qdrant 检索由服务端完成，页面不直连向量库、不提交授权键或显示原始候选。团队文档明确展示“空间成员可访问”或“仅指定成员可访问”，个人文档展示“仅本人”或“与指定成员共享”；模式与角色由真实服务端权限决定。移除直接授权但仍继承空间权限时必须说明，限制特定人读取需先切换受限模式；移出空间和撤销全部独立分享也分别表达。

普通成员增删不更新 Qdrant，不应一律显示“等待知识索引同步”。仅访问模式、归属或正文变化需要索引/策略同步时，按服务端状态显示更新中；新授权/撤权从下一次权限读取生效，已撤权来源不得继续进入后续片段和引用。旧文档启用空间继承前要明确展示生效范围，不自动开放旧私密文档。

Deep Research 入口接收问题和知识域，显示规划、检索、阅读、生成等安全阶段与可回溯来源；内部推理、工具原文和研究笔记留在服务端。最终报告先形成完整草稿；首期改写仅支持明确选择的完整段落，研究报告默认插入新块。正文仅在用户确认后提交，并复核版本和权限。

待审方案开启服务端 checkpoint。断流后先查询原任务：completed 回读完整提案，interrupted 显示“恢复任务”，running 等待原执行退出，终止状态提供复制或重新生成。恢复沿用原 requestId 和目标，调用 resume 后查询最终结果；首期不恢复 token 流，也不拼接旧预览。用户显式取消后不可恢复；来源/目标变化、撤权或预算耗尽时显示对应原因，不能用恢复覆盖当前正文。

编辑器 AI 动作捕获当前已确认目标 → ai-bridge 管理流与草稿 → 完整结果验证 → 用户逐段确认或全部接受 → 服务端结构 owner 原子复核并写入 → 观察协同更新与持久化回执。知识问答/普通 Chat 不直接修改正文；用户选择“用于创作”或“插入文档”后才建立绑定个人文档的新提案，重新校验目标和来源。共享协议见 [ai-contracts](../packages/ai-contracts.md)，React/UI 沿用现有编辑器包的可选入口与受控组件。

#### 空间边界与入口

团队创作支持在团队空间中发起对话、选择有权限的团队资料、讨论和生成草稿；AI 正文写入仅允许个人空间。所有接受操作遵守同一限制，团队管理员也不能写入团队正文。团队原有人工协同编辑继续使用现有会话。首期 Chat 记录与提案归发起主体，各成员可以分别创作；共享聊天记录和跨主体接受提案不在本次范围内。

| 页面上下文                         | Chat / 资料使用                     | AI 正文写入                                    |
| ---------------------------------- | ----------------------------------- | ---------------------------------------------- |
| 本人个人空间                       | 支持；资料仍检查 read/ai 等当前策略 | 具备 write/ai 且空间所有者为本人时支持确认写入 |
| 他人的个人空间或共享给我的个人文档 | 仅在资料使用策略允许时支持          | 不允许写入；可选择本人个人文档作为新目标       |
| 团队空间                           | 支持授权资料的对话、研究与草稿      | 不允许直接写入团队文档；提供“保存到个人空间”   |
| 未选择写入文档                     | 支持 Chat 和讨论                    | 提示选择个人文档或“新建个人草稿”，不静默建文档 |

全局导航增加“AI 创作”，路由拟为 `/ai`。个人文档页通过“AI 创作”打开同一受控面板；团队文档页入口显示“讨论与创作”，带入资料上下文，写入位置保持未选择或明确的本人个人文档。URL 可携带 `sourceWorkspaceId`、`contextDocumentId` 和 `targetDocumentId`，分别表示资料来源与写入目标；它们不携带正文、Prompt、凭据或授权信息，深链恢复时服务端重新授权。

页面顶部不再常驻展示资料来源和写入位置。资料与当前文档分别由对话输入区、画布标题处管理；改变资料不会更换当前文档。空间类型与个人所有者始终由服务端判断，规则见 [服务端空间与写入策略](app-server.md#92-空间与写入策略2026-10-21-设计)。

从团队结果“保存到个人空间”时，先校验资料是否允许用于 AI 以及复制到目标空间，保留来源访问限制。不能直接搬用绑定团队文档的旧批次；用户选择/新建个人文档后创建新 requestId，以该文档已确认快照编译提案。

#### 创作页面布局

桌面沿用全高应用外壳：左导航 288px，可收起至 56px；中间为真实文档画布，右侧为约 380px、可调宽的对话面板。画布优先获得宽度，AI 面板开启时大纲和详情收进按需抽屉。页头、编辑工具栏、正文统计区与输入框固定在各自区域，正文和消息列表各自滚动。

```text
┌────────────┬──────────────────────────────────────────────────────────┐
│ 知书       │ AI 创作                                                 │
│ 工作区     │ 紧凑页头，正文优先获得空间                               │
│ 搜索       ├─────────────────────────────────┬────────────────────────┤
│ 文档       │ Emoji / 文档标题                │ 本次对话     新对话    │
│ AI 创作 ●  │ 固定编辑工具栏                  │ 用户：整理方案大纲     │
│ 收藏       │                                 │ AI：流式草稿与来源     │
│ 最近       │ 新旧对比，每处 [✓] [×]          │ [查看差异] [预览替换]  │
│ …          │ 已接受的结果在此协同呈现        │ 冲突时：草稿已保留     │
│            │                                 ├────────────────────────┤
│            │                                 │ 讨论 · 写作 · 研究     │
│            │                                 │ 输入想法或修改要求…    │
│            │                                 │ 添加资料   发送 / 停止 │
│            ├─────────────────────────────────┴────────────────────────┤
│            │ 修改导航 · 全部拒绝 · 全部替换；统计与服务器保存状态     │
└────────────┴──────────────────────────────────────────────────────────┘
```

未选择文档时，画布显示“把想法，写成一篇文档”，提供“新建个人草稿”“选择已有文档”，并给出从想法起草、整理大纲、基于资料撰写三个轻量入口；对话可以先开始。创建复用应用真实幂等创建流程，不因重试生成多个空文档。选定文档后使用现有 `EditorProvider` / `EditorShell` 和同一协同会话，不建立仅供 AI 的第二份正文状态。

对话支持连续追问、停止、失败重试、复制、展开来源和将回复用于创作。每轮区分“讨论”（只回复）、“写作”（生成目标提案）与“研究”（授权检索后生成带引用提案），写作动作再选择新建、续写、改写、摘要或翻译。普通讨论不写入正文。改写只在能力支持时展示完整段落目标，不把局部选区静默扩大。每条提案卡显示作用位置、摘要、来源、差异及审阅进度。

首期“本次对话”由有序 requestId 关联多轮任务；一轮一个 requestId，服务端从同主体已完成任务解析有界历史，重新检查来源权限，不信任客户端拼装的 assistant 消息或 evidenceId。历史超过保留期时明确提示开启新对话，不以恢复 checkpoint 代替发起下一轮。暂不增加会话列表、消息表或共享聊天房间；Chat 合约扩展见 [ai-contracts](../packages/ai-contracts.md#7-chat-与写入模式扩展2026-10-21-设计)。

#### 段落确认与批量操作

完整结果形成后展示正文新旧对比。每段 ✓ 只接受这一处，× 只拒绝这一处；底部上下箭头定位尚未决定的建议，“全部替换”和“全部拒绝”作用于剩余建议。已拒绝的原文不会被后续全部替换覆盖。新增尾段和删除建议使用同样的控制；逆序接受新尾段仍保持提案中的顺序。

每次决定携带唯一 decisionId、当前审阅 revision 与可选 blockIds，服务端按可信提案生成子批次。接受在 owner 事务中同时记录正文、回执、决定和后续版本；拒绝只记录决定，不增加正文 durableSeq。多标签页、网络重试和重复点击只提交一次。完成部分审阅后，客户端等协同会话到达对应版本，再安装剩余建议，保持同一编辑器挂载。

刷新先授权回读原任务及审阅状态，再对照权威正文恢复剩余建议。断流和 resume 均不修改正文；未知结果先查询原任务，不能把失败当成新决定或重开任务。外部编辑、恢复历史、权限变化仍阻止旧建议，不能借局部接受刷新到他人的新版本。

#### 冲突判断与反馈

冲突由服务端针对版本和权限确定性判断，模型不承担冲突裁决。首期采取整文档保守检查：捕获的 `generationId + durableSeq + baseStructureRevision` 必须仍匹配；即使只是普通文字变化、结构修订没变，也必须阻止旧提案写入。版本复核与结构命令提交在同一 owner 的串行边界内完成，不能先查版本、释放保护、再写入。

| 变化                                                         | 页面与服务端行为                                               |
| ------------------------------------------------------------ | -------------------------------------------------------------- |
| 任一正文变化，包括其他块、同账号多标签页或另一 AI 提案先写入 | 返回冲突；原文保持现状，草稿保留，不自动刷新旧提案基线         |
| 目标删除、版本恢复、新 generation、文档移入团队空间          | 阻止写入；重新选择合法目标后创建新任务                         |
| write/ai 撤销、资料权限/版本失效                             | 阻止写入或交付；敏感草稿按撤权策略隐藏，不能继续展示旧检索片段 |
| 相同决定重复提交或多标签页竞态                               | 返回原 operationId 和权威回执，只产生一次正文变更              |
| 回执未知、网络断开                                           | 标为“待确认”，先回读原操作；不能当失败重新生成并自动插入       |

冲突卡文案为“文档已更新，本次未写入。草稿已保留。”提供“查看当前文档”“对比草稿”“基于最新内容重新生成”；复制仅在权限仍允许时提供。首期不提供强制覆盖或自动合并。其他设备尚未发送的离线修改无法被服务端提前发现，离线恢复继续遵循原协同草稿策略；本设计不承诺自动解决语义冲突。

#### 状态、响应式与验收

生成显示“正在检索 / 正在生成 / 已停止 / 草稿不完整 / 已完成”；应用显示“待接受 / 正在检查 / 已写入 / 发现冲突 / 待确认”；保存状态只采用真实 durable ack。来源卡请求当次授权跳转，失效时显示不可访问。普通讨论无需来源时允许无引用回复，知识问答无依据时必须明确不足，不伪造引用。

宽屏展示画布与对话；空间不足时优先收起导航并将对话改为可切换面板。手机使用“文档 / 对话”标签与固定输入区，适配软键盘和安全区域；切换不销毁编辑器、草稿或任务订阅。对话输入框 Enter 发送、Shift+Enter 换行，中文输入法组合期间 Enter 只交给输入法；按钮具备可见焦点、名称和忙碌状态，阶段变化使用克制的 `aria-live`，不逐 token 播报。亮暗主题复用[界面设计规范](../design-system.md)。

| 验收场景                               | 必须观察到的结果                                                     |
| -------------------------------------- | -------------------------------------------------------------------- |
| 个人文档逐段审阅                       | 完整预览前不可接受；接受后只有一次变更并获真实保存回执               |
| 个人文档全部替换                       | 仅处理剩余建议；已拒绝原文保留，有冲突不写入                         |
| 团队入口与越权请求                     | 可授权讨论；团队正文写入被服务端拒绝                                 |
| 多轮讨论与“用于创作”                   | 普通回复不写入；创作绑定新的个人目标；历史按主体授权且受 TTL 限制    |
| 多标签页、人工输入、同文档两轮 AI 结果 | 任一已确认正文变化使旧提案冲突，包括结构修订未变的文字变更           |
| 断流、取消、恢复和刷新                 | 不完整结果不应用；回读已保存的决定，只有用户操作可写入               |
| 逐段/全部操作竞态与回执丢失            | 原操作只执行一次；查询返回同一结果，界面不虚报成功或失败             |
| 撤权、移动、删除、恢复版本、切换账户   | 权限与代次重新检查；旧任务不写入新目标或新账户，敏感上下文按策略清理 |
| 手机、亮暗主题、键盘、输入法与长对话   | 正文空间、独立滚动、焦点和未提交输入保持连续，无页面横向溢出         |

### 评论与提及

评论正文、线程状态和成员权限由服务端管理；编辑器只呈现锚点装饰。新评论失败保留草稿；目标删除仍可查看讨论并注明上下文丢失。提及候选仅来自可见成员，通知收件人仍需具备目标文档访问权。

| 正文与选区                           | core / collaboration                       | 不复制进 Query、Zustand 或表单全文字段                     |
| AI 创作草稿与提案                    | ai-bridge                                  | 页面订阅投影；段落决定由服务端持久化，避免重复应用         |
| 旧 Chat 历史与任务结果               | authoring feature + Query / 生成客户端     | 保留迁移基线，新会话使用下述业务组件库，不同时维护两份投影 |
| 侧栏、弹窗、密度                     | 本地 React state；确有跨页共享再用 Zustand | 不把远端数据搬入全局 store                                 |

按 `features/documents / spaces / knowledge / authoring / comments / settings` 聚合页面、表单和 query 组合；路由只组装 feature。`api/generated` 来自 app-server OpenAPI，不手写平行 API DTO；WebSocket 与 SSE 使用对应协议适配器，不强行套进普通 JSON mutation。

### AI Chat 业务组件库

2026-10-24 明确为两个应用业务封装：协作写作 WritingChat 和知识问答 RagChat。它们均组合 [chat-ui](../packages/chat-ui.md)基础组件，不新增前端 workspace 包；本次完整实现规划以 WritingChat 为主。RAG 继续使用 LangChain，组件复用不改变它的执行引擎或协议。

#### 业务边界

| 维度     | WritingChat                                      | RagChat                                     |
| -------- | ------------------------------------------------ | ------------------------------------------- |
| 场景     | 协作文档创作、改写、提案审阅、写作调研和图片产物 | 知识域问答、来源与引用、答案历史            |
| 后端     | 官方 DSH 内核封装的 dsh-agent                    | LangChain RAG 问答服务                      |
| 视图来源 | chat-contracts 写作快照/事件、写作插件产物       | RAG API 的答案、来源、请求与实际流状态      |
| 业务动作 | 接受/拒绝提案、审批工具、插入产物                | 引用定位、调整检索范围、追问、转入写作      |
| 状态归属 | 自己的写作会话、DSH Run/attempt、草稿与审批投影  | 自己的 RAG 会话、问答请求、答案预览和来源   |
| 展示复用 | MessageList、Composer、内容块、状态、主题和插槽  | 相同基础组件；引用等业务展示由 RagChat 提供 |

不使用一个带引擎切换参数的会话控制器来同时驱动两个 Chat。转换场景时由明确业务动作交接授权内容/引用，再创建对应业务请求；原会话保留，RAG 历史不直接装载为 DSH Session。

#### 落位与依赖

建议按实际实现创建以下目录，简单逻辑可合并，不预先创建空壳模块：

```text
apps/app-web/src/
  components/
    ui/                              # 现有基础 UI 原语
    writing-chat/
      writing-chat.tsx               # WritingChat，组合 chat-ui
      writing-chat-session.ts        # 写作事件、Run、attempt 与审批状态
      writing-chat-transport.ts      # 写作命令、快照与 SSE
      writing-chat-projection.ts     # 写作状态到基础组件 Props
      use-writing-chat.ts            # React 生命周期
      index.ts
    rag-chat/
      rag-chat.tsx                   # RagChat，组合相同 chat-ui
      rag-chat-session.ts            # RAG 会话、问题、答案与来源状态
      rag-chat-transport.ts          # LangChain RAG 服务 API
      rag-chat-projection.ts         # 答案/来源到基础组件 Props
      use-rag-chat.ts
      index.ts
  features/ai/                       # 写作页面、资料选择、提案/产物业务
  features/knowledge/                # RAG 页面/入口、知识域与引用定位
```

页面/feature 依赖各自业务组件库；两个组件库都依赖 chat-ui 和应用公共身份/缓存基础设施，不互相依赖状态或 transport。WritingChat 消费 [chat-contracts](../packages/chat-contracts.md)，RagChat 消费其 RAG API 的生成类型，按需复用纯视图/引用类型。认证、SSE 解析等实际已重复的基础设施可复用应用公共能力，业务 reducer、请求与缓存分别维护。

资料选择器、写作审阅及产物 renderer 按 feature 提供，通过插槽/回调注入组件库，组件库不反向导入 feature。现有 ai-creation-page、ai-message-card、ai-client 属于旧写作实现，按本次 WritingChat 边界迁移；不能据文件中包含 Chat 就将 RAG 也迁入 DSH。

#### 状态和生命周期

| 状态                               | 唯一 owner                      | 使用规则                                            |
| ---------------------------------- | ------------------------------- | --------------------------------------------------- |
| 写作消息、Run、审批、cursor 与预览 | WritingChat 会话状态            | 从写作快照/事件构建，chat-ui 受控消费               |
| RAG 问题、答案、引用、请求与预览   | RagChat 会话状态                | 从 RAG API 构建，不套用写作 Run/审批状态            |
| 文本与附件草稿                     | 对应 Chat 或调用方，二选一      | 只清理已受理版本，期间新输入保留                    |
| 列表、权限摘要和知识域/资料目录    | TanStack Query / 生成客户端     | 查询键包含业务种类、租户/主体和资源，不复制消息投影 |
| 写作目标与审阅                     | 写作 feature / editor-ai-bridge | 正文操作通过既有协同链路                            |
| 焦点、浮层、滚动和临时高度         | chat-ui / 当前宿主控件          | 就近管理展示状态                                    |

每个业务会话一个状态 owner；Hook 建立和释放对应订阅，StrictMode 重挂载不重复提交请求。按业务种类、会话身份和请求代次隔离迟到事件，WritingChat 与 RagChat 同时显示时互不覆盖。退出/切换身份清理对应内存投影和连接。

写作迁移后不再由每张卡片独立轮询任务；写作审阅查询不能成为第二份消息历史。RAG 查询和状态策略沿用其实际 API，并单独处理请求取消、重试和最终答案。

#### 写作加载、发送与恢复

1. 读取经校验的 writing 草稿，获取服务端授权快照，用 cursor 订阅后续事件；历史分页只替换声明范围。
2. 按 eventId/sequence 去重、检查顺序；流预览按 streamEpoch/attemptId/revision/index 归并，完整消息替换预览。断档或 cursor 失效重新同步。
3. 生成稳定 clientMessageId/idempotencyKey，展示 pending；受理成功仅清理已提交草稿，结果未知沿原身份查询/重发。
4. cancel 等待写作服务端确认；SSE 断开只停止订阅。重新生成、resume 原 interrupted Run 和重连分别处理。
5. 断线采用有界退避和抖动，401/403 或撤权停止重连，旧 attempt 的 delta 不追加。

审批按 approvalId/decisionId 提交单次决定；重复、冲突、过期和迟到决定依服务端记录处理。提案接受/拒绝、调研报告转文档、图片插入由写作业务回调完成，正文成功以协同 durable ack 为准。

#### RAG 问答接入

RagChat 调用 LangChain RAG 问答 API，提交问题、知识域/资料引用和其协议支持的历史引用，展示真实答案、来源与引用。检索候选在服务端授权，引用打开再次校验；证据不足、检索失败与无权限分别反馈。RAG 不直接修改协作文档。

流式输出、最终结果查询、重试、取消和恢复只展示 RAG 服务实际支持的能力；不因底层 UI 有对应卡片就提供虚构审批、DSH resume 或持久化 cursor。复用组件也不要求 RAG 将现有事件重新编码为写作协议。

“用于写作”明确交给 WritingChat：重新校验答案来源的可用性，捕获写作目标的已确认版本，创建独立写作会话/请求。它不改变原 RAG 会话归属，也不重解释原 LangChain checkpoint。

#### HTTP/SSE、缓存与安全

两个 transport 分别使用对应 OpenAPI 生成客户端；流读取使用各自协议 adapter，共用应用 API 配置和动态认证。写作消费 DSH 产品 HTTP/SSE，RAG 消费 LangChain 问答 API；浏览器不加载服务端内核。

公共 SSE 解析可处理 UTF-8 分片、CRLF、多行 data、心跳、Content-Type、大小限制和 reader 释放；业务解码与恢复游标分别处理。写作确认事件推进 cursor，临时 frame/心跳不推进；RAG 仅使用自己的协议位置。停止一个 Chat 或关闭其连接不影响另一个。

草稿/cache/query key 至少包含 writing/rag、API、租户/身份、业务上下文、conversationId 和对应协议版本。IndexedDB 读取校验大小、版本和资源引用，缓存失败保留内存草稿；离线编辑不自动补发旧输入。未确认预览与已保存结果分别呈现。

附件上传、动态凭据、安全错误映射沿用应用能力；token 不进入 URL、状态或草稿。刷新凭据后不沿用旧 token 闭包，未登录、撤权、限流和服务故障分别反馈。授权附件只提交资源引用，未完成上传或权限失效阻止发送。

#### 迁移与验收

WritingChat 验证真实 DSH 写作链路，包括幂等、草稿竞态、乱序/断档、预览替换、切会话、重连、取消、审批和协同写入；RagChat 单独验证 LangChain 问答、证据不足、引用定位、历史和实际取消/恢复能力。本次不新增 RAG 执行能力。

独立 chat-ui 示例使用两组受控视图：RAG 答案/引用与写作工具/提案。应用验证两个业务组件同时挂载时消息、草稿、凭据上下文、取消和缓存互不串用。浏览器包不引入 DSH/LangChain 的服务端运行时或 provider 凭据。

## 7. 完整状态与权限反馈

所有页面覆盖 loading、empty、error/retry、无权限、只读、请求中、成功和部分失败。列表删除失败保留原条目，移动操作冲突提供重新加载，后台索引失败显示原因/重试入口，避免仅弹出短暂 toast。

退出/切换账户时断开会话、取消请求并清除该身份的缓存；离线副本依部署策略处理。分享、导出、管理成员等入口遵守服务端 action 能力，并在提交时接受服务端再次拒绝。

破坏性操作、历史版本恢复、格式转换损失与放弃未保存正文均通过应用 `ConfirmDialog` 呈现对象、影响和进行中状态；失败会保留确认内容并显示错误。浏览器刷新/关闭时继续由应用离开拦截和原生浏览器提示处理。

业务只读与浏览器网络故障分别表达。审批中限制哪些操作由服务端策略给出；界面不能自行把“看不到编辑按钮”解释为“内容受到保护”。

## 8. 质量与交付

独立文档配置下不请求知识库/模型初始化接口，不出现配置缺失报错；完整平台配置通过能力发现增加入口。最低演示链路为创建 → 双端协作 → 保存 → 关闭重开 → 恢复版本。当前浏览器验收在本地独立前后端和 PostgreSQL 上通过：编辑中文正文后 durableSeq 从 2 增至 24，刷新并重新登录后正文及服务端序号均恢复；单独的版本验收覆盖命名版本元数据、旧/当前 Block 差异和确认恢复后的新 generation。生产身份接入仍未覆盖。

验收覆盖桌面/窄屏、键盘/输入法、多标签页、慢网/断网、长标题/长文档、附件失败、权限变更、AI 冲突和引用失效。性能目标引用文档地图，不在此复制另一套指标。M3 需从有授权的知识来源走通索引、问答、引用查看与 AI 插入的完整路径。
