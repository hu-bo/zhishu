# 知书界面设计规范

知书的界面以持续写作、阅读和查找为中心。使用中性色底面、克制的靛蓝强调色、清楚的文字层级和轻量反馈，保持中文产品体验。

## 视觉基础

| 元素 | 约定                                                                                 |
| ---- | ------------------------------------------------------------------------------------ |
| 主题 | 浅色使用白色纸面与浅灰画布；深色使用炭灰分层。品牌、成功、警告、危险分别使用语义变量 |
| 字体 | 系统无衬线字体与中文字体回退；代码和快捷键使用等宽字体                               |
| 文字 | 正文 16px / 1.85；界面正文 13–14px；辅助信息 11–12px；页面标题 26–32px               |
| 圆角 | 控件 10px、卡片 16px、弹窗 20px、菜单 12px                                           |
| 间距 | 以 4px 为步进；内容分组 20–32px；弹窗内边距 20–28px                                  |
| 按钮 | 默认 40px、小号 36px、图标按钮 28–36px；触控设备交互目标至少 44px                    |
| 表单 | 输入框默认铺满可用宽度；标签在上、输入在下；边框与细焦点环表达输入状态               |
| 阴影 | 卡片轻阴影、浮层软阴影；导航与正文用细边框分区                                       |

主题定义在 `apps/app-web/src/styles/globals.css`，应用基础组件位于 `src/components/ui`。`--zhishu-ui-*` 将主题传给独立的 `editor-ui` 包。

HeroUI 的 `text-muted` 表示辅助文字，其颜色必须对应 `--muted`。应用的浅色背景使用 `bg-secondary`，避免把背景色映射给组件库的辅助文字。

## 页面与交互

- 导航使用低对比背景与轻量选中状态。桌面显示侧栏，窄屏使用抽屉；空间内编辑只保留一个文档顶栏。
- 文档与空间列表共享页面标题、筛选、搜索和卡片规范。文档标题支持两行；列表不显示内部身份标识。
- 筛选与搜索排序分行，筛选在窄屏可横向滚动。正文与页面根容器不因标题或工具栏产生横向滚动。
- 菜单项的图标、名称和状态始终横向排列。图标不收缩，危险操作使用独立语义色与分隔线。
- 普通弹窗居中；文档面板在窄屏呈底部面板，并保留安全区域。标题与正文只有一层主要容器。
- 搜索高亮使用浅色背景，支持方向键、Enter、Escape。编辑器选区保留链接快捷键的作用域。
- 编辑器保持正文、固定工具栏和底部状态连续。快捷键帮助位于底部；未接入的宿主能力不显示入口。
- 阅读模式保留查找、大纲与有权限的分享；用户选择阅读模式与服务端只读权限独立。
- 图标与标签直接在面板内编辑；技术详情与细粒度授权按需展开。保存、同步和连接状态仍由真实状态驱动。
- 焦点可见，输入法组合期间保留原有按键语义，减少动态效果的系统偏好适用于界面动画。

## AI 创作页面（2026-10-21 设计）

沿用同一应用外壳，以正文画布为中心，右侧约 380px 的 Chat 面板独立滚动。正文使用现有固定工具栏、排版和统计区；对话使用轻量消息与提案卡，不用大量装饰卡片挤占写作空间。模式控件放在页头，使用“手动 / 自动写入”分段选择，默认手动，并持续显示本轮实际模式。

“资料来源”与“写入位置”分别展示，团队资料可以参与授权讨论，AI 正文目标仅限本人个人空间。没有写入目标时提供新建/选择个人文档；不能以禁用整个 Chat 代替空间限制。页面不显示模型工具原文、内部推理、向量库或 SDK 术语。

生成中的文本留在对话预览区，两种模式都不逐 token 修改正式正文。手动提案提供差异与接受按钮；自动提案显示检查与写入结果。冲突使用警告语义、说明文字和可执行入口：“文档已更新，本次未写入。草稿已保留。”网络结果未知显示“写入结果待确认”，成功只采用真实应用/持久化回执，状态不只依赖颜色。

窄屏优先保留正文空间，手机以“文档 / 对话”切换并保留编辑器和输入状态，输入区适配软键盘与安全区域。阶段更新克制播报，中文输入法组合时不接管 Enter，亮暗主题和键盘焦点保持一致。完整布局、空态与交互验收以 [app-web 的 AI 创作设计](apps/app-web.md#知识问答与-ai-创作)为准；本节为后续页面规范，不表示已经实现。

## 交付范围

本轮覆盖 `app-web` 的应用外壳、文档工作台、知识空间、目录浏览、编辑与阅读、搜索、创建表单、分享、导入导出、图标标签、详情、版本和空间成员设置，以及这些页面使用的共用控件。公共分享页沿用同一主题。

示例与设计参考工程保持独立，通用编辑器视觉与宿主能力判断沉淀在 `packages/editor-ui`。
