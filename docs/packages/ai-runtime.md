# ai-runtime：统一助手编排设计

状态：2026-11-13 新目标。原同名包已经退役，下一轮按当前职责重新实现；不恢复原 LangGraph/Deep Agents 运行图。完整规格见 [主技术文档](../apps/ai-assistant-and-public-qa.md)。

## 唯一责任

ai-runtime 通过 dsh-agent 运行同一 Agent，并组合 ai-plugins 中实际允许的插件。它连接本轮输入、服务端策略、原生执行和经校验结果，不建立另一份 Session、模型循环、数据库或产品调度。

一段内部会话可以问答、调研、创建草稿和继续编辑。问答/创作只是本轮意图；明确的 create-draft 是真实用户命令，不能由模型建议或意图切换自动触发。结果统一交给应用产品存储。

## 依赖与边界

依赖 dsh-agent、ai-plugins 和纯合约；不依赖 apps、Fastify 或业务数据库。宿主注入授权、证据、预算、产物、目标操作和真实持久化端口。只在真实边界注入，不为每个步骤建立 service/adapter 转发层。

模型与工具执行只通过同一个 DSH Loop。当前 ai-qa 的引用/证据/结果门槛迁入纯校验和插件规则，不能继续维护独立问答生成器；当前 ai-writing 的编译、工具与 native 接入分别迁入对应责任包。

## 执行要求

- 当前身份和入口策略决定允许插件，用户选择是其子集；公开入口固定只读批准资料。
- 受理时固定命令、上下文修订、目标和实际生效插件；本轮意图不是权限凭据。
- 知识事实回答必须经过证据与引用门槛；用户未要求创建草稿时不创建文档。
- 上下文/授权变化后过滤来源及派生历史，重建正确原生上下文，不能只隐藏前端消息。
- 原生完成事实及已落库结果可补交，未知结果明确中断，不重放正文或图片副作用。
- 预览编排在 `src/preview.ts`：dsh-agent 转发的 text/thinking/tool 帧按原通道透传，工具参数流（tool-args）在本层按工具输出契约解码出可展示正文并入 text 通道（重新编号为一条密集 delta 流），问答与创作因此逐字“打字”呈现；原始 JSON 参数不离开本层，思考与工具步骤不写进持久消息。
- 产品租约、幂等、Run 状态、计量和 outbox 仍由应用服务拥有，本包不创建第二套权威状态。

## exports 与清理

仅提供当前助手所需入口。禁止 ./legacy-authoring、旧 ./chat 运行图、policy 兼容出口、双协议解析及旧包转发。纯内容 Hash/证据/Citation 合约继续沿现有唯一来源，不因恢复本包名搬出第二份实现。

独立消费检查验证统一执行和插件组合，不能继续用“出现 ai-runtime 包名即失败”的旧黑名单。已发布 migration、SDK 当前原生恢复和正常文档历史不属于旧 AI 兼容路径。
