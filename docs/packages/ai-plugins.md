# ai-plugins：问答、research 与写作插件设计

状态：2026-11-13 新目标。当前有效工具/编译器位于 ai-writing，下一轮迁入本包。产品流程、数据库和前端布局以 [主技术文档](../apps/ai-assistant-and-public-qa.md) 为准。

## 插件能力

| pluginId | 提供的能力                                        | 实际约束                                                   |
| -------- | ------------------------------------------------- | ---------------------------------------------------------- |
| scope    | 解析资料范围意图，连接同一个范围控件/授权端口     | 不扩大权限，不另外调用模型来维护范围状态                   |
| rag      | 平台检索、来源读取、带依据回答及引用校验          | 一份检索和证据规则，未取得有效依据时说明不足               |
| research | 组合平台资料及允许的 Tavily 搜索/提取，整理结论   | 不启动研究 Agent，不自动创建草稿                           |
| writing  | 讨论写作、按命令生成 draft/proposal、编译合法结构 | 初始文档由明确创建命令控制，后续修改通过审阅与 durable ack |
| image    | 已有图片任务、审批和资产引用                      | 真实幂等任务和结果状态，不把 UI 预览当持久化完成           |

research 和 rag 共用平台搜索/读取工具，writing 可直接使用已经允许的资料工具。Tavily 由宿主 WebSearchPort 注入，不把 ai-qa 或其他完整 Agent 封装成工具。

## Skill 与工具

Skill 包含随包发布的指令、使用条件及必要资源；插件提供当前 Schema 和可信工具实现。按需加载说明，但权限、预算、证据和输出门槛在服务端强制执行。清单静态随包代码维护，不新增注册表、市场、脚本执行平台或通用插件框架。

插件不依赖 ai-runtime、apps、路由或业务数据库，不持有会话单例。工具接收受控端口，在当前 Run 下登记稳定 toolCallId 和产物，禁止跨会话可变状态。

## 证据与来源

使用 ai-contracts 唯一的 EvidenceBundle/Citation、WritingProposalPayload 等纯合约。来源元数据只存在 evidence 的 sources，items 引用来源身份；生成产物只保存 evidenceRefs，Run 记录实际提供给模型的全部来源。

文档引用可定位 documentId/blockId，网页引用保存受校验标题、URL、检索时间和实际摘录类型。quote 必须匹配已登记证据。来源随正文采纳、保存重开、复制和导出保留，不能只留在 Chat 卡片。

## 文档与联网边界

模型建议不创建文档。用户明确点击创建草稿后，宿主受理 create-draft 命令，初始化正常文档并绑定同一会话；插件只生成校验后的材料和操作，不绕过 documents/collaboration 直接写库。

TAVILY_API_KEY 仅在服务器配置，插件只拿到可信搜索/读取端口，不接收实际密钥。Search 的供应商自动答案不作为原文；摘要与正文提取分开，失败、限流、取消和未知用量明确表达。公开入口没有联网、图片或写作工具。

## 迁移与独立消费

从当前 ai-writing/tools、compiler、contracts、skills 迁移有效能力，复用 rag 和纯合约，删除旧包及重复工具。参考版本的旧 AuthoringProposal/SourceCitation 格式和关键词检索不能作为兼容分支回归。

纯合约/编译子入口不加载 DSH 执行内核；插件资源必须包含在发布文件中。独立消费验证真实工具及证据规则，应用侧验证权限、事务、持久化和 UI。
